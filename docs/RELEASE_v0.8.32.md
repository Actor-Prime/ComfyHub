# ComfyHub v0.8.32

## 新增

- **AMD 显卡与核显支持（本地模型）**：本地模型组件自动识别 AMD / Intel 显卡，改用 Vulkan 后端推理（38 MB，独显 / 核显 / 老卡通吃）；NVIDIA 仍走 CPU 包，不跟出图抢显存。
- **AMD 显卡支持（ComfyUI 出图）**：按显卡型号自动匹配 gfx 架构并安装对应 ROCm 版 PyTorch（RX 7000 / 9000、Strix Halo 核显）。Radeon 780M / 760M / 740M 这类不在官方列表的核显，自动按 gfx1100 家族内核运行并注入 `HSA_OVERRIDE_GFX_VERSION`。
- **`tools/amd_gpu_doctor.py` 环境诊断脚本**：一条命令看清内存、显卡、gfx 架构、页面文件、以及「这台机器能跑哪一档模型」的结论，支持 `--ram 16` 模拟其他机器。
- **运行中切换本地模型**：服务跑着时直接在下拉里换模型，按钮会变成「应用并重启」，一次点击完成停止 + 启动，不用自己按两次。

## 优化

- 本地模型启动失败不再只有一条红条：llama-server 的输出会进环形缓冲，崩溃或超时时把最后几十行写进控制台日志，现场可直接看到崩在哪一步。
- 服务运行中切到「尚未下载」的模型时，「下载模型」按钮会正确变成可点状态（此前会一直显示「模型已就绪」且点不动）。
- 本地模型的说明文案按实际后端生成：AMD / Intel 机器写「用 Vulkan 在显卡上推理」，核显写「按 CPU 推理（核显卸载实测更慢）」，不再一律写「纯 CPU」。
- 显卡信息展示更准确：AMD 卡显示型号 + 核显/独显 + gfx 架构 + 该走哪条加速路径；不再承诺当前架构下装不上的方案。

## 修复

- **修更新内容弹窗一次都没弹过**：对话框构造完没有调用 `exec()`，窗口从未显示。同时修掉「先推进版本号再取说明」的顺序问题——取不到说明时会把版本号提前推到新版，导致这次更新提示永久丢失。
- **修 Intel 12 代及以后 CPU 上本地模型服务一启动就崩**（`0xC0000374`）：官方 llama.cpp 包自带的 LLVM OpenMP 运行时在混合架构 CPU 上初始化阶段越界写堆。现在自动换成兼容的 Intel OpenMP 运行时并重试，原文件备份为 `libomp.dll.orig`，可随时还原。
- 修 AMD 用户装好 ROCm 版 PyTorch 后被启动门卫拦下的问题（ROCm 版 `torch.version.cuda` 为空，此前被误判成 CPU 版）。
- 修若干条与实现脱节的测试断言（下载源数量、显卡文案、OpenMP 测试桩未还原、更新弹窗版本数量写死）。

---

**注意**：本次 AMD 支持在 Intel + NVIDIA 机器上完成代码验证与回归，**AMD 实机尚未验证**。Radeon 780M 等核显的家族内核兼容属实验性方案，若启动失败请参考 `docs/AMD_780M_QWEN_IMAGE.md` 第 10 节的退化顺序。
