# ComfyHub v0.8.39

## 新增：远程实例（连另一台机器 / 云镜像）

- **实例设置里多了一个「连接方式」**：`本机实例` / `远程实例`。选远程后只需要填一个地址，例如 `http://192.168.1.20:8188`（只写 `IP:端口` 也行，会自动补 `http://`），或云镜像平台给的那个 `https://xxx.platform.com`。
- **认证支持四种**：不需要 / Bearer Token / 账号密码（Basic）/ 自定义请求头（`X-API-KEY` 之类）。Token 与密码用 Windows DPAPI 加密保存，配置文件里看不到明文；界面也不会把已保存的凭证回填成明文显示。
- **「测试连接」按钮**：保存前先打一次 `/system_stats`，失败会按原因分开说——连接被拒绝 / 域名解析失败 / 证书校验失败 / 认证失败 / 超时，不再只丢一句「连不上」。
- **能做什么**：提交工作流、看队列、中断任务、取图、看系统与显存状态、批量跑、AI 助手工具、任务完成通知，全部走 ComfyUI 的 HTTP API，和本地实例一模一样。
- **不能做什么（界面已明确禁用并给出原因）**：启停远端进程、内核升级、插件安装、pip 依赖修复、模型库扫描、读本地日志——这些都依赖本机文件系统。远程实例上这些页签/按钮直接不可用，不会再点了报错。
- **LLM 侧也认这套**：AI 助手的 `control_instance` / `get_logs` 对远程实例会明确拒绝并说明原因，不会回报「已启动」让用户去远端扑空。

## 修复：外部已启动的实例认不出来

以前 `is_running()` 只认 ComfyHub 自己拉起的子进程，于是：

- 用户自己 `python main.py` 起的 ComfyUI，界面显示「未运行」，按钮全灰；
- SSH 隧道映射过来的另一端实例，同样显示未运行，等于没法用。

现在补了一层探活：`/system_stats` 返回并带 `system` / `devices` 特征字段才算「运行中」——只看 TCP 端口会把「端口被别的程序占着」误判成实例在跑，所以没有采用更省事的端口探测。探活在后台线程做、结果缓存 2 秒，不会阻塞界面（这是 0.8.2x 那轮卡顿事故的教训）。

外部实例的「停止」按钮会置灰并提示「该实例不是本程序启动的，请到它的窗口/命令行停止」，避免点下去报错。

## 修复：远程实例出图后「文件不存在」

远程实例生成的图在远端磁盘上，原来 `_collect_images()` 直接用 `os.path.isfile()` 校验本机路径，结果全部判 missing——AI 会回报「出图完成但文件不存在」。

现在本地找不到时改走 ComfyUI 的 `GET /view` 把图下载到 `%LOCALAPPDATA%\ComfyHub\remote\<实例名>\`，返回真实本地路径。顺带修好一类老问题：本地实例如果自定义过 `--output-directory`，以前同样读不到图。

## 其他

- CLI 同步支持远程：`ComfyHub.exe status / list / batch` 对远程实例按 `base_url` 探活与执行；`--autostart` 对远程实例会明确拒绝。
- 实例配置自愈补齐 `kind / comfyui_path / python_path / port` 默认值，老配置不受影响（缺失即视为本机实例）。
- 新增英文词条，`_FlowBox` 两列布局下远程表单不会残留空位。

---

**怎么用（连另一台机器 / 云镜像）**

1. 远端 ComfyUI 必须监听可达地址（`--listen 0.0.0.0`，且防火墙/安全组放行端口）；只给 SSH 的平台可以先用 `ssh -L 8189:127.0.0.1:8188 root@主机` 建隧道，然后地址填 `http://127.0.0.1:8189`。
2. 本机打开「ComfyUI 管理」→「实例设置」→ 连接方式选「远程实例」→ 填地址与认证 → 点「测试连接」→ 保存。
3. 之后提交工作流、看队列、取图、批量跑都照旧；启停与非本地功能请在那台机器（或云平台控制台）操作。
