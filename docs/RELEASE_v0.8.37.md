# ComfyHub v0.8.37

## 修复

- **「补装依赖」不再像卡死**：原来 pip 的输出被整段缓冲（`capture_output=True`），进程退出前界面上一行字都没有 —— 卡在依赖回溯 20 分钟和 2 秒就失败，长得完全一样。现在改成逐行流式读取并实时写进日志，`Collecting…`、`Downloading…` 都能看见；日志第一行固定写「已开始 / 未开始：原因」，任何时候都能回答「到底动没动」。
- **补装可以随时终止**：运行中按钮变成「取消并终止」，点了直接杀掉 pip 进程树（不留后台任务）。连续 5 分钟没有任何输出时，日志会先给一行明确提示并把按钮解锁；连续 10 分钟无输出则自动中止该插件，不再让人干等到 2 小时超时。单个插件的总时长上限也从 7200 秒降到 1800 秒。
- **ComfyUI 正在运行时不再「点了没反应」**：旧流程只弹一句「补装依赖前请先停止 ComfyUI」，关掉弹窗后界面回到原样、日志空白，看着就像卡住。现在直接给「停止 ComfyUI 并继续」按钮，点完自动停机（最多等 30 秒）再接着补装；不点则明确记一行「未开始：…」。
- **插件目录不完整（缺 `__init__.py`）单独识别**：`custom_nodes\minimax-h3` 这类「目录在、`requirements.txt` 齐全、却没有 `__init__.py`」的空壳，自检原来显示「齐 (12)」，而 ComfyUI 启动一直在报 `[Errno 2] … __init__.py` + IMPORT FAILED。现在这类目录显示红字「目录不完整」，并给一个「删除」按钮（补依赖对它无效）；判定是静态的，只认三种形态：目录为空、缺 `__init__.py` 且顶层没有任何 `.py`（老式平铺插件不误报）、多套了一层同名目录。
- **修「缺包归错人」**：`[XB-llama] llama-cpp-python 未安装（本地模型不可用，其余节点正常）` 这句被当成「minimax-h3 缺 llama_cpp」，横幅于是推「一键补装」，点进去装 `llama-cpp-python` —— 方向全错，永远修不好。两处改动：可选探测噪声补上中文形态（其余节点正常 / 本地模型不可用 / 可选依赖…），就近归属收紧为「往后不跨汇总行、往前只认紧邻 2 行且那行本身不含失败词」；目录不完整的插件不再推荐补装。
- **取消或中止后自动跑 `pip check`**：把互相冲突的包列进日志，只提示不自动回滚（自动卸包比半装更容易连带弄坏别的插件）。
- **窗口最大化后左边（顶部）留 1~2 px 桌面**：实测最大化后 x=0 整列是壁纸颜色、x=1 起才是窗口底色。原因是圆角只在启动时设过一次、从不跟随窗口状态，最大化后既没切直角也没去掉 DWM 那圈 1px 描边。现在窗口状态一变就同步 `DWMWCP_DONOTROUND` + `DWMWA_BORDER_COLOR=NONE`（还原时回到圆角 + 默认描边），并对 ≤4 px 的几何偏差做一次贴齐屏幕工作区的修正。

## 改进

- 插件依赖自检对话框：表格里「目录不完整」的行用红字说明原因，鼠标悬停给出完整路径与处理建议；表头摘要会单独统计「另有 N 个插件目录不完整」。

---

建议 v0.8.36 及更早版本升级：补装卡住、目录空壳、最大化缝隙三件事都在这一版处理。
